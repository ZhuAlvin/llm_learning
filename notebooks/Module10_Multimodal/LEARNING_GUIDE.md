# Module 10: 多模态小模型应用 - 学习手册

> 📖 **本指南与 README 的关系**：README 提供模块概览和快速导航，本学习指南则提供详细的学习路径、深度解析和实践建议。建议先阅读 README 了解模块全貌，再按本指南深入学习。

## 1. 本模块解决什么问题

本模块聚焦“把视觉 AI 从服务器带到边缘”，核心问题是：

- 图像/视频场景下模型种类繁多，如何根据业务约束（延迟、精度、功耗）做出可量化的选型决策？
- 通用模型在具体场景（安防、零售、医疗）中效果不佳，如何系统化地做领域适配？
- 视频流是连续信号而非单张图片，推理管线需要怎样的架构才能做到实时、不掉帧？
- 边缘设备资源极度受限（< 4GB 显存），如何把模型压到能跑、同时保持可接受的精度？

统一业务主线：`通用多模态平台`——构建一个支持图片/视频理解的轻量级多模态平台，面向安防监控、零售分析、医疗影像等多个下游场景，按需微调、边缘部署。

`业务场景 → 模型选型 → 最小实现 → 指标评估 → 领域适配 → 边缘部署 → 成本取舍`

每章的固定学习链路：
1. **先读问题**：这一章要解决什么业务痛点
2. **建立直觉**：核心思想的生活化类比（不碰公式）
3. **最小实现**：最简代码跑通一个 demo
4. **深入公式**：理解为什么这样设计
5. **工程优化**：从 demo 到可上线还有多远
6. **常见坑**：前人踩过的坑和避坑方法

## 8. 常见卡点与应对

- **卡点**：timm 模型加载后 forward 报 shape mismatch
  **应对**：检查输入尺寸是否匹配模型预期（通常 224×224），使用 `model.default_cfg` 查看

- **卡点**：YOLO-nano 在自定义数据上不收敛
  **应对**：确认标注格式（xywh 归一化）、anchor 尺寸是否匹配目标尺度、学习率是否过高

- **卡点**：视频推理管线 CPU 占用 100% 但 GPU 利用率低
  **应对**：瓶颈在预处理（解码/resize），用 NVIDIA DALI 或移至独立线程池

- **卡点**：ONNX 导出后推理结果与 PyTorch 不一致
  **应对**：检查 ONNX opset 版本、输入归一化方式（mean/std 是否正确嵌入模型）、使用 `onnxruntime.InferenceSession` 的 `providers` 参数指定后端

- **卡点**：INT8 量化后精度断崖式下降
  **应对**：校准数据集不够代表性，至少 500 张覆盖各种光照/角度/场景；或切换到 QAT 训练 1-2 epoch

- **卡点**：Docker 容器内无法使用 GPU
  **应对**：确认安装了 nvidia-container-toolkit，运行时加 `--gpus all` 参数

- **卡点**：多 LoRA 切换时推理延迟 spike
  **应对**：预加载所有权重到显存，通过指针切换而非文件 IO；用 LRU (Least Recently Used, 最近最少使用) 缓存策略管理

- **卡点**：视频流 RTSP 断连导致管线崩溃
  **应对**：增加重连逻辑（指数退避）、健康检查心跳、降级到备用流

- **已学完 M01-M05 的 NLP 方向学习者**：重点关注知识迁移，LoRA/Attention 等概念在 CV 中几乎一致，额外需要补的是视觉特有概念（卷积、感受野、数据增强）
